## 2. 算法逻辑

### 2.0 公共约定

- 价格/重量数组一律 **1-based**（`price[1..n]`、`weight[1..n]`，下标 0 不用）；
- 只求最优值，**不保存方案**；
- 表/状态值用 `int`；`n · max(p_i)` 超过 `2^31−1` 会静默溢出（见 §4）；
- 假设 `w_i ≥ 1` 且为整数。

### 2.1 `base()` — DP-1（基线）

```
P[0][j] = 0
P[i][j] = max{ P[i-1][j], P[i-1][j-w_i] + p_i }
```

- 时间 `Θ(nc)`，空间 `Θ(nc)`（二维整表）。
- 缺点：最好情况与最坏情况一样慢——即使大量格子是平台值或不可达，也照样填满。
- 实现注意：`table[i][0]` 的初始化会读未初始化的 `weight[0]`（当前数据 `w ≥ 1`，
  结果不受影响，但属于 UB，见 §4）。

### 2.2 `dpwithlist()` — §3.4 DP-with-Lists

**状态与列表**

```
状态 (w,p)：某个子集占 w 容量、得 p 利润
L_j       ：只考虑前 j 件物品时的全部「非支配」状态，
            按 w 严格递增（因而 p 也严格递增）排列，w ≤ c，首元素恒为 (0,0)
```

`j` 不存储在状态里：它是层号（外层循环变量），等价于 DP 表的行下标；同一层内所有
状态的剩余物品集合都是 `{j+1..n}`，所以层内可直接比较支配关系。

**支配（dominance）**

```
(w,p) 支配 (w',p')  ⟺  w ≤ w' 且 p ≥ p'（且至少一个严格）
```

直觉：支配者是「更轻却更值钱」的替身，任何能接在被支配者后面的后续选择，
接到支配者后面仍然可行且不更差 ⇒ 被支配状态可安全删除。

**每层三步**（`L_{j-1} → L_j`）

1. **平移**：`L' = { (w + w_j, p + p_j) : (w,p) ∈ L_{j-1} }`
   —— 对应「选第 j 件」；保序，故 `L'` 仍有序。
2. **截断**：删掉 `w > c` 的部分（`w_j > 0` ⇒ 溢出的必是后缀，可 `break`）。
3. **归并 + 支配删除**：把 `L_{j-1}`（不选）与 `L'`（选）按 `w` 归并，
   顺序扫描并只保留「利润严格递增」的项——三种情况：

   | 情况 | 条件 | 动作 |
   |---|---|---|
   | A | `s.p ≤ last.p` | `s` 被支配（或重复）→ 丢弃 |
   | B | `s.p > last.p` 且 `s.w == last.w` | `last` 被支配 → 用 `s` 替换 |
   | C | `s.p > last.p` 且 `s.w > last.w` | 互不支配 → 追加 |

   只需与**结果列表尾部**比较一次即可判定（更早的状态更轻且更不值钱），故每状态 O(1)。

**答案**：`L_n` 最后一个状态的 `price`，即 `z_n(c)`。

**复杂度**：设 `B = max_j |L_j|`。

```
每层 O(|L_{j-1}|)，总计 O(nB) ≤ O(nc)        空间 Θ(c)（只需两层）
B 的四个上界：B ≤ c+1 ，B ≤ Σp+1 ，B ≤ |可达重量和| ，B ≤ 2^j
```

**关键实践结论**（实测，`-O2`）：列表法**不是**恒快于基线。
每层要做「平移 B + 归并 2B + 写回 2B」约 `5B` 次元素操作，而基线是 `c` 次；
状态是 8 字节 `struct`、有三条分支、且每层一次 `malloc/free`，实测常数 `α ≈ 10`。于是

```
加速比 ≈ (c / B) / α        ⇒  只有 B < c/10 左右时列表法才真的更快
```

| 场景 | B 的量级 | 结果 |
|---|---|---|
| `Σp ≪ c`（利润值域小 / 容量巨大） | `≤ Σp` | 快 16–44×（对一维基线） |
| 早期层 `2^j ≪ c` | `≤ 2^j` | 前 `log₂c` 层显著快 |
| `Σp ≈ c`、随机实例（即本仓库 testdata） | `≈ c` | **慢 ≈10×** |
| 强相关 `p = w+10` | `≈ c`（支配几乎失效） | **慢**，需要 §3.5 |

### 2.3 `dpbound()` — §3.5 DP-with-Upper-Bounds（待实现）

思路：把 §3.4 的列表当成**分支限界树**——状态 `(w,p)` 即「前 j 件已固定」的节点。

- 上界取**分数背包（LP 松弛）**：
  `V(w,p) = p + ` { 剩余物品 `j+1..n` 在容量 `c−w` 下的分数背包最优值 }；
- 维护当前最好可行解 `z`（贪心 / maximal-prefix 解即可；任何状态的 `p` 也是可行解值）；
- 若 `V(w,p) ≤ z` 则 **fathom**（删除该状态），其余仍按 §3.4 归并去支配；
- 复杂度：界按朴素 O(n) 算 ⇒ `O(n²c)`；用前缀和 + 双指针摊还 O(1) ⇒ `O(nc)`；
- 价值：支配在**强相关**实例上几乎无效（`B ≈ c`），而界剪枝不依赖 (w,p) 的相对关系，
  在这类实例上仍能大量删状态。

### 2.4 三者关系速查

| | `base` (DP-1) | `dominance` (§3.4) | `bounding` (§3.5) |
|---|---|---|---|
| 剪枝依据 | 无 | 支配（状态两两比较） | 分数背包上界 + incumbent |
| 需要额外输入 | — | — | 一个可行解（贪心即可） |
| 最坏时间 | `Θ(nc)` | `O(nB) ≤ O(nc)` | `O(n²c)` 朴素界 / `O(nc)` O(1) 界 |
| 最好时间 | `Θ(nc)` | `O(n)` | 更小（列表被剪到极短） |
| 空间 | `Θ(nc)` | `Θ(c)` | `Θ(c)` |

## 3. 正确性验证（已完成）

- **手算用例**：`n=3, c=10, (6,5)(5,4)(4,3)` → 11；
  `n=2, c=4, (3,2)(1,3)` → 3。
- **随机对拍**：`n ≤ 8, c ≤ 25` 共 200 000 组，与子集枚举暴力比较，
  `base` / 一维滚动 DP / `dpwithlist` **三方答案全部一致**（`0/200000` 错）。
- **内存检查**：以上对拍在 `-fsanitize=address,undefined` 下无报错。
- **数据文件**：27 个 `testdata` 实例上三者答案一致。
